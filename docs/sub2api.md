- 后端：Go + Gin + Ent

- 缓存/队列：Redis 7+

## 能力清单

这是它和 CLIProxyAPI 最大的差别——**它是平台，不是工具**。

| 能力 | 说明 |
|---|---|
| 多账号管理 | 多账号订阅池，OAuth 接入 |
| API Key 分发 | 给下游用户签发 key |
| Token 级计费 | 用量追踪与成本计算 |
| **拼车共享** | 核心卖点，按 token 摊分成本 |
| 智能调度 | 粘性会话、429 自动切换、负载均衡、Composite 分组路由 |
| 并发/速率限制 | 按用户、按账号配置 |
| 内置支付 | 易支付、支付宝、微信、Stripe（需另装 `sub2apipay` 之类的支付网关） |
| 管理后台 | Vue 3 面板，账号健康检查、用户管理、一键更新/回滚 |
| Codex 兼容 | 原生兼容 Codex CLI，支持透传；修过 `max_output_tokens` 兼容问题 |

## 关于「关闭注册」

**sub2api 是自部署开源项目，没有中心化注册入口。** 所以「关闭注册」通常指这两件事之一：

1. **第三方搭的 sub2api 中转站**关了注册——社区里有人抱怨「某个 sub2api 网站注册功能暂时关闭半个多月」，回帖澄清那是**某个中转站的名字**，不是项目本体
2. **自建者主动关注册**——有站长没改默认管理员密码，被 87 个 IP 盗用、一天涌进 60 多个注册，之后就把注册关了并加 Cloudflare 验证

> 若在 GitHub 上看到「关闭」，多半是作者关了 Discussions（`gh api` 实测 `has_discussions: false`），跟注册无关。

**仓库当前状态正常**：`archived: false`、`disabled: false`、当日有提交。

> 另有一条**未经一手核实**的传闻：有文章称 sub2api 因 OpenAI 压力「已宣布不再将部分核心功能开源」。抓原文后发现**没有版本号、没有公告原文、没有一手出处**，纯作者转述。**存疑，别当事实。**

## 风险（必读）

### 官方点名过

OpenAI Codex 负责人 **Tibo Sottiaux** 回应 Codex 额度缩水争议时明确提到：

1. 受影响的用户里，相当比例在**用 sub2api**
2. 把订阅转成 API 流量后**对外转售或分享给多名用户**，不是 OpenAI 支持的用法，**这类流量会被反欺诈风控系统标记**
3. 个人凭 Sign in with ChatGPT 正常使用不受影响

**后续反转**：Tibo 补充说目前未发现整体用量系统异常，sub2api 只是「一种特定情况」，不能解释所有用户配额耗尽问题。

### 拼车这个形态本身的风险

- 官方点名的关键词是 **「分享给多名用户」**——拼车正好落在这个词上
- 社区共识：「最大风险就是拼车高并发」。有反馈 1 个 Pro 组多人车、高并发不做会话隔离 → 判定账号共享
- 有说法建议「最好 2 人车」「最多 2 个号放池子里用」
- **连坐**：拼车中有人破限、跑爬虫，会连累整车
- 多号最好走不同代理出口，避免一个出事连坐

### 账号级失效

ChatGPT 和 Codex **共用账号体系**。封号 = 网页版 + Codex CLI + API key **一起失效**。不可逆。

### 若要降低风险

- **人数越少越好**（2 人 vs 5 人风险差很多）
- 不做会话隔离之外的高并发；限制并发数
- 号池不要堆太多号
- 正价自付，不用代开/礼品卡/虚拟卡
- 约定拼车成员不做破限/逆向/爬虫
- **用小号开池，别拿主号赌**

3. 检查出网限制

### Nginx 反代的坑

用 Nginx 反代配合 Codex CLI 时，必须在 `http` 块加：

```nginx
underscores_in_headers on;
```

否则 `session_id` 等带下划线的头会被丢弃，破坏多账号粘性会话路由。
